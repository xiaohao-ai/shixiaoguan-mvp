# 评测方案

> 文档性质：MVP评测契约。最后更新：2026-09-03。

## 1. 评测目标

试销官的首要目标不是证明“爆款预测准确率达到 90%—95%”，而是证明：

1. 它能把模糊新品需求转成可执行、可审计的实验；
2. 它知道数据不足时不能得出强结论；
3. 它的数字、阈值和决策可复算；
4. 它能将证据稳定转换成 Go/Pivot/No-Go 和下游打样/首单任务，并在证据不足时输出 Evidence Insufficient；
5. 相比人工表格流程，它能减少整理与决策时间，同时保留人工控制权。

因此评测分为数据、实验、预测、决策、Agent执行、业务价值六层。不同层的指标不得混写成一个“总准确率”。本轮 P0 不运行预测模型，第三层所有预测指标统一报告为 `N/A`，不用合成数据填充效果数字。

## 2. 数据状态标签

每个评测报告和界面必须显示以下一种状态：

- `SYNTHETIC`：人为构造的演示数据，只验证流程与逻辑。
- `PUBLIC_SAMPLE`：许可允许的公开样例数据，说明来源和使用边界。
- `USER_PROVIDED`：用户上传数据，尚未完成企业授权验证。
- `ENTERPRISE_AUTHORIZED`：企业明确授权用于约定范围的数据。

只有 `ENTERPRISE_AUTHORIZED` 数据完成离线回测后，才能对企业场景给出对外预测效果数字。

本轮 P0 的试销观测只允许 `SYNTHETIC`。其他三种枚举为后续兼容契约，不表示当前已实现上传或企业接入。不设置含义重叠的 `SIMULATED` 状态。

该约束必须由服务端而非 UI 保证：创建和更新 Brief 时提交其他来源均应返回 `422`。用户上传图片后，`data_sensitivity_level` 应从 `SYNTHETIC_ONLY` 变为 `USER_CONTENT_RESTRICTED`，但 `data_origin` 仍为 `SYNTHETIC`。

## 3. 第一层：数据质量

### 检查项

- 必填字段覆盖率；
- 重复记录率；
- 缺失值与异常值；
- 曝光、点击、收藏/询单/加购、购买意向的合法上游关系是否满足；
- 日期、渠道、基础款、配色变体和实验版本是否可关联；
- 价格、花费与购买意向口径是否一致；`order/refund/return_count` 仅作为合成场景的后续冲突辅助信号，不是主指标，也不被表述为真实成交或退货成效；
- 实验组流量是否严重失衡；
- 是否存在未来信息泄漏或标签穿越。
- 场景 ID、生成器版本、固定随机种子、Schema 版本和快照哈希是否完整；
- 相同计划版本、场景版本、生成器版本、Schema 版本与固定种子重放是否产生同一快照哈希；
- 同项目重置是否将旧数据集置为非活跃，从当前分析视图排除旧观测，但保留观测行、对象版本与审计记录；
- 每个实验臂是否满足曝光≥300且购买意向≥10；
- 50/50 目标分流的 SRM 卡方检验是否出现 `p<0.01`。

### MVP 验收

- 所有场景数据快照都有数据状态、场景 ID、生成器版本、随机种子、生成时间、Schema 版本和哈希。
- 必填字段缺失时不得静默继续。
- 严重质量问题必须触发 `quality_status=BLOCK` 且 `decision_outcome=EVIDENCE_INSUFFICIENT`，而不是伪造置信结论。
- Evidence Card 能列出已发现问题及其对结论的影响。
- 每个领域 QualityIssue 都有稳定 `issue_id`、`code/rule_code`、affected fields/record refs、observed/expected 和 handling_status；请求级 Schema 错误仍直接返回 `422`。
- 相同计划、场景、种子、Schema 和生成器版本在重置前后的完整数据集 SHA-256 一致；决策已批准时重置请求 100% 返回 `409`。

## 4. 第二层：实验有效性

### 需要回答的问题

- 测试的究竟是款式、价格、素材、人群还是渠道？
- 对照组与实验组除目标变量外是否尽量一致？
- 样本量、运行周期和停止条件是否在实验前定义？
- 是否因为看到中途结果而随意停止？
- 是否把曝光后行为当成分组条件，导致选择偏差？
- 平台无法随机分流时，结论应降级为什么等级？

### 指标

- 实验计划字段完整率；
- 随机化/准实验条件满足率；
- Sample Ratio Mismatch等质量告警；
- 最小可检测效应与样本量说明覆盖率；
- 推断强度枚举合法率：`CAUSAL / QUASI_EXPERIMENTAL / ASSOCIATIONAL / UNDETERMINED`。

### MVP 验收

- 每个实验只允许一个主要决策目标，可配置次要观察指标。
- 首个实验只比较同一男士轻量休闲鞋基础款的两个配色变体；价格、人群、渠道、素材和卖点必须一致。
- 系统在计划批准前锁定主指标、阈值、预算、周期和停止规则。
- `DemoPolicy` 的每次修改必须生成新版本；已批准快照不可覆盖。批准后的变更必须使当前计划/下游投影失效，并新建实验版本重新审批。
- 无法支持因果判断时，界面必须明确写“相关性信号”，不得伪称因果提升。

## 5. 第三层：预测与不确定性

本轮 P0 不实现销量、爆款、售罄或四种 `decision_outcome` 类别概率预测模型。评测报告必须写：

```text
prediction_model = N/A
prediction_metrics = N/A
reason = "P0 uses synthetic data and deterministic DemoPolicy v1; no enterprise-authorized backtest is available."
```

不得对合成场景计算 MAE、WAPE、Brier Score 等值后对外宣称模型效果。下列基线、切分和指标是获得 `ENTERPRISE_AUTHORIZED` 数据后的后续评测契约，不属于当前 MVP 验收。

### 后续基线

至少比较：

1. 简单人工规则或总体均值；
2. 同类/相似款均值；
3. 季节性朴素基线（有时间序列时）；
4. 候选机器学习或时序模型。

复杂模型只有稳定优于简单基线才进入默认流程。

### 后续数据切分

- 按时间向前滚动切分，禁止随机混入未来数据。
- 新品冷启动评测应按款式或款式族留出，避免同一SKU泄漏到训练与测试。
- 价格、活动、曝光等只能使用预测时真实可知的协变量。
- 单独报告不同品类、渠道、价格带和数据充足度下的结果。

### 后续指标

- 点预测：MAE、WAPE；仅在目标值不接近零时参考MAPE。
- 概率预测：Pinball Loss、预测区间覆盖率及区间宽度。
- 四种 `decision_outcome` 类别概率：Brier Score、校准曲线、Precision/Recall 和混淆矩阵；只在未来拥有真实历史标签时启用。
- 排序任务：Top-K命中、Spearman相关或NDCG，可用于“先测试哪些款”，不能替代销量误差。

### 对外表达规则

- 必须同时报告样本量、时间范围、基线、指标定义和置信区间。
- “准确率”只可用于定义明确的分类问题；不能把方向命中、销量误差和置信度混成一个百分比。
- 在没有真实历史决策标签时，不发布所谓“爆款准确率”。

## 6. 第四层：决策质量

### 金标准

使用三类来源建立黄金案例：

- 规则可确定的合成场景；
- 由产品负责人预先标注的业务场景；
- 未来由鞋企专家复核的真实历史案例。

每个案例包括输入快照、期望决策、允许的备选决策、关键理由、禁止出现的结论和下游动作。

合成金标案例必须覆盖 `DemoPolicy v1` 的每个边界：曝光 299/300、购买意向 9/10、SRM `p` 值在 0.01 两侧、购买意向率 3% 边界、相对提升 15% 边界、毛利率 40% 边界、`MOQ×单位成本=预算` 边界和交期硬约束通过/失败。

组合真值表还必须覆盖：明确低需求＋轻微可修改经营失败仍为 No-Go；任一不可修改经营失败为 No-Go；恰好一个可修改失败为 Pivot；两个及以上可修改失败为 Evidence Insufficient；全部通过才为 Go。任何一个组合都不得因模型解释而改类。

### 指标

- 决策一致率：相同输入是否得到相同结构化结论；
- 证据忠实率：理由是否能追溯到真实字段或规则；
- 证据三维完整率：每条证据是否同时具有 `statement_type`、`inference_strength` 和 `evidence_grade`；
- 证据语义一致率：是否避免把 `OBSERVED` 直接等同于 `CAUSAL`，或把模型文字当作独立观测；
- 数值可复算率：所有比率、利润、Wilson 区间、首单离散情景点和阈值能否由代码复现；
- 拒绝正确率：数据不足时是否正确拒绝强判断；
- 政策/经营约束违反率：是否违反MOQ、毛利底线、预算和交期；
- 工厂交接门禁正确率：是否仅在符合决策与审批组合时生成允许的草稿类型；
- 决策后悔值：相对历史真实结果或最优可知策略的损失，获得真实数据后启用。

### MVP 验收

- 黄金案例中结构化输出schema通过率为100%。
- 黄金案例中证据三维完整率和枚举合法率为 100%。
- `SYNTHETIC` 数据的 `evidence_grade` 不得高于 `B`、`inference_strength` 不得高于 `ASSOCIATIONAL`；`quality_status=BLOCK` 时必须为 `D`。B 级不得被解释为真实市场或因果证据。
- 确定性数字可复算率为100%。
- 禁止性主张（伪造来源、无数据声称95%、越过审批执行）为0次。
- 低证据场景必须输出降级或拒绝结论。
- 数据质量为 `BLOCK` 时，100% 输出 `EVIDENCE_INSUFFICIENT`，不输出其他三类结果。
- 已批准 Go 且当前 Brief 版本的首单假设已由具名操作者确认，才能生成完整 TechPack Lite 草稿；Pivot 还必须批准精确修订版本，批准后仅有打样草稿和带水印的条件式首单建议。每个保守/基准/进取值是离散点，三点整体形成情景范围；未确认假设、No-Go 或 Evidence Insufficient 的交接对象数为 0。

## 7. 第五层：Agent 可靠性

### 指标

- 端到端任务完成率；
- 在线决策解释只读 evidence tool 的调用成功率；
- 确定性应用服务（质检、指标、规则、状态、首单、交接）的成功率；
- 非法状态跳转次数；
- 人工审批绕过次数；
- 前端从 workflow 状态错误推断审批通过的次数（目标 0；必须读取对象 `approval_status`/确认对象）；
- schema校验失败率；
- 幻觉字段/不存在来源引用次数；
- 单任务时延、模型调用次数和估算成本；
- 同一固定输入的关键决策稳定性。
- 逻辑业务 Agent 角色数（P0 恒为 1）、handoff 数（恒为 0）；SDK 可按结构化任务创建多个短生命周期调用实例，不能把实例数误算成业务 Agent 数；
- Brief 归一化和实验计划文字调用的工具数为 0；在线 `EXPLAIN_DECISION` 只挂载一个无参数 `read_locked_decision_evidence`，必须以命名 `tool_choice` 首次调用，其返回值仅含应用锁定的类别、原因码、证据和限制；
- 在线 DeepSeek `deepseek-v4-flash` 的模式标记与逐运行推理强度记录正确率：Brief/计划默认 `low`，强制命名工具的决策解释为 `none`；仅设置旧 `OPENAI_API_KEY` 时仍须保持回放，根启动器不得把模型凭据注入 Web 子进程环境、不得把遗留 OpenAI 凭据注入任一子进程，并须拒绝 `NEXT_PUBLIC_*` 模型凭据误配置；Key 不得进入日志、数据库、报告或 Git；
- 离线回放 `(input_sha256, prompt_version, output_schema_version)` 三元键命中率，以及未命中返回 `422 REPLAY_RECORDING_MISS` 且状态不推进的正确率。

### MVP 验收

- `workflow_state`、`quality_status`、`decision_outcome` 三个核心正交状态的所有变化写入事件日志；四个 Gate 的每次审批都作为绑定目标 ID 与精确 `object_version` 的不可覆盖 `Approval` 记录。
- 实验计划、DecisionCard、仅 Pivot 需要的 PivotRevision、当前 Brief 版本首单假设四个门禁不可绕过；首单确认记录的 actor、time、target ID 和 Brief version 可审计。
- 模型/回放失败时保留输入哈希和失败原因；严格回放 miss 不生成 Agent 成功记录，也不改变业务状态。
- Agent不得自行修改已批准实验的主要指标和停止规则；修改必须生成新版本并重新审批。
- 不完整 Brief 必须保持 `DRAFT`；从已批准计划或交接草稿新建 Brief/DemoPolicy 版本时，当前计划及下游投影为空、活跃数据集为 0，但历史 ObjectVersion/Approval/Observation/Audit 记录数不减。
- 活跃项目未带 `cancel_active_work=true` 时归档必须返回 `409`；成功归档后的 Brief 和 DemoPolicy 写入 100% 返回 `409`。
- 成功归档后的模拟创建、推进、完成或重置请求也必须返回 `409`。
- 同一 `Idempotency-Key` 的并发相同请求在单应用进程内只执行一次并回放同一响应；同 key 不同请求指纹 100% 返回 `409`。
- 金额输入覆盖 SQLite `2^63-1` 后端边界、JavaScript 安全整数前端边界、元转分舍入和两位小数显示，不允许溢出或静默丢失精度。
- 在线解释与离线录制对同一已锁定 DecisionCard 均不得改变确定性决策类别、原因码和数值；解释文本可不同。

## 8. 第六层：业务价值

企业试点前只定义测量方法，不预先编造效果。

### 建议指标

- 从候选款进入到决策卡产出的周期；
- 单批候选款人工整理和沟通工时；
- 每个有效实验成本；
- 打样前淘汰/改款比例；
- 首单售罄、缺货、滞销和毛利表现；
- 退货原因回流覆盖率；
- 从市场信号到改款/补单建议的响应时间；
- 决策被业务人员采纳、修改或驳回的比例及原因。

### 首个真实试点建议

- 选择一个品类和一个渠道；
- 选取3—10个候选款；
- 与企业原有人工流程并行，不直接替代；
- 预先约定成功指标和停止条件；
- 比较周期、工时、证据完整性和决策差异；
- 至少完成一次结果回收与复盘后再对外描述价值。

## 9. Demo 黄金场景

每个场景都使用同一男士轻量休闲鞋基础款的深灰蓝、米白 2 个配色变体，保持价格、人群、渠道、素材和卖点不变，并使用固定场景版本和随机种子。至少准备以下场景：

1. `GO`：需求信号、毛利和供应约束均通过。
2. `PIVOT_PRICE`：点击与加购信号达到演示兴趣门槛，但购买意向不足，只能将价格/报价摩擦列为待复测假设；不声称已估计价格的因果效应。
3. `PIVOT_DESIGN`：一个配色的购买意向率达到 3%，另一配色未达到，且两者相对差异至少 15%；保留主体、修订弱配色并复测。
4. `NO_GO`：质量可用，但两个配色的购买意向都处于明显低位（演示默认不高于 1%），或整体点击率不高于 6% 且需求未全部达标。
5. `INSUFFICIENT_DATA`：样本不足或关键字段缺失。
6. `INVALID_EXPERIMENT`：组间流量或变量控制存在严重问题。
7. `SUPPLY_CONSTRAINT`：固定场景只覆盖需求通过且 MOQ/预算缺口在可修改范围内，因此预期 Pivot；不可修改的更大预算缺口和超过可修改天数的交期失败分别由独立单元测试覆盖 No-Go，不能把这些测试分支说成同一固定场景同时发生。
8. `CONFLICTING_SIGNALS`：核心信号方向相互冲突，必须输出 `EVIDENCE_INSUFFICIENT` 并要求人工复核。

当前 P0 没有真实成交与退货结果；任何场景都不得声称已验证真实销量、退货风险或商业效果。

## 11. 实施验证记录

### 2026-09-03 DeepSeek 单场景在线冒烟

- 仅使用 `GO` 合成场景与本地内存/忽略提交的 Key，未发送原始个人数据；模型为 `deepseek-v4-flash`。
- `NORMALIZE_BRIEF`：`LIVE`，`reasoning.effort=low`，结构化 Schema 通过；单次 5,942 ms，输入/输出 Token 为 669/535。
- `GENERATE_PLAN_TEXT`：`LIVE`，`reasoning.effort=low`，结构化 Schema 通过；单次 6,684 ms，输入/输出 Token 为 659/579。
