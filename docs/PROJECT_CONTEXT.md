# 项目上下文

> 文档性质：跨任务稳定背景。最后更新：2026-09-03。

## 1. 赛事与命题

- 赛事：永嘉农商杯相关 AI 创新赛事。
- 赛道：赛道一“人工智能体（AI Agent）”。
- 命题：命题 1“AI Agent × 鞋服产业”。
- 通用要求：项目需立足永嘉产业发展实际，以 AI + OPC 的轻量化方式解决产业数字化升级问题，并保证原创、自研、资料真实合规、无知识产权纠纷。

### 主办方给出的产业事实与痛点

主办方认为，永嘉鞋服产业已经形成生产制造、品牌销售和供应链配套一体化体系，同时存在：

- 款式迭代慢；
- 设计研发效率低；
- 供应链协同繁琐；
- 私域运营人力成本高；
- 客户需求响应滞后；
- 柔性生产适配不足。

主办方列出的方向包括智能设计、穿搭推荐、柔性供应链、私域运营、智能客服及其他创新方向。

### 项目采用的事实原则

主办方给出的痛点是本项目的第一性约束。互联网研究只能补充产业现状、验证竞品和校准方案，不能反过来替代命题本身。

## 2. 参赛者条件

- 单人参赛。
- 当前岗位：AI 产品经理。
- 过往能力：新媒体、内容/IP运营经验，可理解内容假设、用户反馈、渠道实验和转化链路。
- 当前限制：暂时接触不到鞋企，没有企业内部经营数据，也没有稳定的鞋类行业专家团队。
- 后续可能性：赛事方或企业未来可能提供数据与专家反馈，但在正式获得前不能把它写成已承诺资源。

这意味着首版必须具备低依赖、可替换数据源、人工可校正、容易演示的特点，不能从重 ERP、全工厂排产或高精度预测开始。

## 3. 已选产品方向

### 暂定名称

`试销官`

可替代工作名：新品快反决策 Agent、新品实验指挥 Agent。最终品牌名尚未确定。

### 一句话定位

面向永嘉中小鞋企的 AI + OPC 新品快反决策与实验编排 Agent：连接现有设计工具和企业授权渠道，把低成本试销证据转成可审计的 `Go / Pivot / No-Go / Evidence Insufficient` 四种结果，并仅在通过相应审批后生成允许的鞋类打样与首单草稿。

### 它解决的核心问题

企业真正困难的不是“能否再生成一张鞋款图”，而是：

> 在投入打样、备料和量产之前，怎样以更低成本判断哪个款值得继续、哪个款需要修改、哪个款应该停止，并把判断及时传递给后续打样和供应链。

### 产品性质

它不是单一预测模型，也不是内容生成器，而是一个决策与实验系统：

- 主动拆解新品假设；
- 规划试销变量、样本人群、预算、周期和止损线；
- 由应用服务运行 P0 场景加载、质量检测、统计分析、状态机、审批与经营约束；授权数据导入属于后续能力；
- 输出带证据充分性、推断强度、风险和缺失数据说明的建议；
- 经人工批准后生成下游可执行数据包。

### MVP 执行基线（2026-09-03 冻结）

- Demo 品类：男士轻量休闲鞋，1 个基础款＋2 个配色变体；首个实验只比较配色，价格、人群、渠道和素材保持不变。
- 应用形态：本地优先的可运行 Web 应用＋演示后端，不用纯高保真原型替代数据、状态和审计闭环。
- 数据入口：本轮 P0 仅使用预置场景控制台中固定随机种子生成的每日聚合合成数据；CSV、手工录入和平台 API 均不属于本轮 P0。
- 来源与敏感性：项目创建和 Brief 更新由服务端强制试销来源为 `SYNTHETIC`；用户图片附件只将独立的 `data_sensitivity_level` 标为 `USER_CONTENT_RESTRICTED`，不能把合成试销观测改称用户或企业数据。
- Agent：使用 OpenAI Agents SDK 的单一逻辑编排 Agent；Brief 归一化和实验文字草案不挂载工具，只有在线决策解释在该次调用中挂载一个无参数、只读的锁定证据工具。数据校验、指标、四态决策、状态转换、审批和工厂交接均由应用确定性服务直接执行，不是 Agent tools，也不是独立 Agent。
- 模型：在线默认 `gpt-5.6-terra`，低推理强度；只有 `MODEL_MODE=live/auto` 且存在 API Key 才在线运行。否则只按 `(input_sha256, prompt_version, output_schema_version)` 严格命中固定录制，未命中返回 `422 REPLAY_RECORDING_MISS`，不得动态伪造回放。
- 预测：本轮不训练或运行销量/爆款预测模型，预测指标统一显示为 `N/A`。
- 状态：只有 `workflow_state`、`quality_status`、`decision_outcome` 三个核心正交维度；审批是版本化 Gate 记录。
- 证据：每条陈述分别记录 `statement_type`、`inference_strength`、`evidence_grade`；合成数据的证据等级最高为 B、推断强度最高为 `ASSOCIATIONAL`，且不得形成真实市场因果主张。
- 分类优先级：质量阻断 Evidence Insufficient→冲突信号 Evidence Insufficient→明确低需求 No-Go→不可修改约束 No-Go→恰好一个可修改失败 Pivot→全部通过 Go→其他 Evidence Insufficient。明确低需求不能被轻微经营约束升级为 Pivot，多个可修改失败也不能合并成 Pivot。

## 4. 为什么优先做这个方向

### 与主办方痛点的对应

| 主办方痛点 | 试销官的作用 |
| --- | --- |
| 款式迭代慢 | 在打样/量产前缩短候选款筛选和改款反馈周期 |
| 设计研发效率低 | 为设计提供有证据的保留、修改和淘汰建议 |
| 供应链协同繁琐 | 用结构化打样包与首单三点情景减少口头反复 |
| 私域运营成本高 | 后续可调用私域 Agent 执行分群试销与回访 |
| 客户需求响应滞后 | 将用户反馈结构化并快速回流商品决策 |
| 柔性生产适配不足 | 用小单验证、首单三点情景范围和补单触发条件衔接柔性生产 |

### 与个人能力的匹配

参赛者的新媒体经验不是产品身份本身，而是理解“内容—人群—反馈—转化”实验链路的能力来源；AI 产品经理能力负责把这条链路产品化、规则化和 Agent 化。

### 与永嘉已有能力的关系

永嘉及国内已经存在 AI 设计、数字样衣、选款、ERP、供应链和客服能力。试销官不应替代它们，而应成为设计与生产之间的决策编排层。

## 5. 竞争判断

### 已确认的接近产品

- First Insight：数字概念/产品测试、消费者反馈、需求与价格预测、商品组合和首单深度，是最接近的直接竞品。
- MakerSights：消费者共创、草图/产品线验证和购买意向研究。
- MESH01：目标用户的实物、合脚度、舒适度和性能测试。
- Stylumia：新品需求、选款和商品组合预测。
- Centric Software：从趋势、PLM、企划到定价、库存与销售的企业级套件。
- RELEX、Blue Yonder：下游商品计划、补货和供应链 Agent。
- 国内知衣科技、VALI/惠利玛、Style3D、百胜、伯俊、数云分别覆盖趋势设计、数字样衣、商品运营、供应链或私域能力。

### 可以说的创新

- 聚焦永嘉中小鞋企和鞋类本地工艺语义；
- 将试销实验、证据决策、打样交接和首单三点情景压缩成轻量闭环；
- 以 OPC 微订单方式提供低门槛服务；
- 连接既有设计、ERP/MES、供应链、私域和客服工具；
- 对数据来源、计算过程、人工审批和决策变化进行审计。

### 不可以说的创新

- “全球首个新品预测 Agent”；
- “市场上完全没有竞品”；
- “能够预测爆款且准确率达到 90%—95%”；
- “已经打通永嘉企业真实系统”或“已经产生真实降本数据”（在完成真实接入前）。

## 6. AI + OPC 的项目表达

本项目把 OPC 理解为：由单人或小团队借助 AI、标准化工具和可插拔连接器，为中小企业承接可量化的数字化微订单。

未来获得企业授权数据后的微订单示例（不是本轮 P0 数据入口）：

- 为 3—10 个候选鞋款建立实验方案；
- 导入一次授权试销结果并进行数据质检；
- 输出证据卡、款式去留/改款建议；
- 生成一份结构化打样任务与首单三点情景范围；
- 在真实结果回收后完成一次决策复盘。

商业模式只作为假设，待企业访谈验证：按新品批次、SKU 数量或月度订阅计费，并提供本地化数据适配和人工专家复核增值服务。

## 7. MVP 成功定义

MVP 不以“训练出高准确率爆款模型”为完成标准，而以一条纵向闭环可运行、可解释、可回放为标准：

1. 用户创建一个男士轻量休闲鞋项目，录入 1 个基础款、2 个配色变体及经营约束。
2. 系统生成结构化 Product Brief 与试销实验计划。
3. 用户批准计划，在预置场景控制台加载固定种子、每日聚合且明确标记的合成数据。
4. 系统识别数据问题，必要时拒绝做强结论。
5. 系统按版本化 `DemoPolicy v1` 生成 Evidence Card 和 Decision Card；决策类别始终是 `Go / Pivot / No-Go / Evidence Insufficient` 四种，预测指标为 `N/A`。
6. 四类审批门精确绑定对象版本：实验计划、决策、仅 Pivot 需要的 `PivotRevision`、当前 Brief 版本的首单假设；`Evidence Insufficient` 不能批准进入交接。
7. 已批准 Go 且首单假设已确认时生成 TechPack Lite、打样任务和三个离散首单情景点；Pivot 还必须先批准精确修订版本，仅生成打样草稿和带水印的条件式三点情景；三个点整体形成保守到进取的情景范围，不是每点的统计区间。No-Go 与 Evidence Insufficient 不生成工厂交接物。
8. 全流程能够展示来源、对象版本、审批人/时间和决策依据；对象快照与事件追加保留，不用当前投影覆盖历史。

## 8. 数据策略

### Demo 阶段

- 公开产业资料用于背景，不直接等同于企业经营数据。
- 本轮 P0 的试销观测只来自预置场景控制台：按日、实验臂和配色聚合，固定随机种子，并强制标记 `SYNTHETIC`。
- 该限制由后端创建/更新接口强制；客户端提交 `PUBLIC_SAMPLE / USER_PROVIDED / ENTERPRISE_AUTHORIZED` 会被拒绝。图片附件采用独立敏感级别，不改变数据来源。
- 数据来源状态契约保留 `SYNTHETIC / PUBLIC_SAMPLE / USER_PROVIDED / ENTERPRISE_AUTHORIZED` 四种枚举，但后三种在本轮 P0 不能产生。
- 控制台只允许选择、运行、重置和回放预置场景，不允许通过滑块或表单临时调整数据以追求特定结论。
- 同项目重放会停用旧数据集、清空当前派生投影，但保留旧观测、对象版本、模型运行和审计记录；决策批准或交接生成后不能再重置。
- CSV/Excel 上传、手工观测录入、公开数据导入和平台 API 改为后续增强，不属于本轮 P0。
- 页面和导出必须显示场景 ID、生成器版本、随机种子、数据状态与“仅验证流程/规则，不代表真实市场效果”。

### 企业接入阶段

优先补充以下最小字段：款号、品类、图片/属性、价格、成本、曝光、点击、收藏/加购、成交、退款退货、尺码颜色、库存、交期、MOQ、历史相似款和活动信息。

任何模型报告都必须注明数据覆盖期、样本量、缺失率、分布变化和适用范围。

## 9. 长期蓝图

```text
市场/趋势信号
      ↓
智能设计 Agent → 候选款
      ↓
试销官 → 实验、证据、决策、打样包、首单三点情景范围
      ↓
柔性供应链 Agent → 采购、排期、外协、补单和风险
      ↓
私域运营 Agent / 客服 Agent → 反馈、复购、退货原因
      └──────────────────────→ 决策数据回流
```

长期目标可以是行业 Agent 网络，但首版必须保持“一个逻辑编排 Agent＋应用确定性服务”的边界；只有在线决策解释该次 SDK 调用拥有一个无参只读证据工具。

## 10. 已解决与仍待验证的问题

O-001 至 O-009 已在 2026-09-03 由 `docs/DECISIONS.md` 的 D-012 至 D-020 解决。以下不再阻塞 MVP 开发，但仍是获得真实企业证据后的复审项：

- `DemoPolicy v1` 的阈值只是合成演示契约，必须经真实企业数据回测才能调整为业务政策。
- TechPack Lite 已冻结为“通用鞋类＋男士轻量休闲鞋扩展”，但工艺、鞋楦、大底和验收字段仍需企业样单或专家校验。
- 企业数据入口的格式、授权、脱敏和指标口径仍待试点；在此之前不开启 CSV 或平台连接。
- 产品工作名“试销官”和视觉品牌仍待目标用户验证。

当前实现还允许在任一未归档状态显式创建新的 Brief 或 DemoPolicy 版本：当前下游投影失效并回到 `DRAFT` 或 `BRIEF_READY`，历史账本继续保留。项目归档是显式操作；活跃工作需同时确认取消，归档后禁止再修改。
